# AST 变换与语义验证

先固定原始样本与散列，识别语法类型、sourceType、严格模式和模块入口。派生结果与原始输入分开。用户只要阅读视图时可改善可读性，但明确它是否能执行；用户需要可执行等价产物时必须验证行为。

优先检查 source map 是否存在并匹配该 bundle，随后区分压缩、转译、打包器和真正混淆。webpack 规则不能直接套到 ESM、Rollup 或 Vite 的所有输出。

## 工具选择

- 独立变换优先使用项目已有 Babel parser/traverse/types/generator；解析插件和版本与输入匹配。
- webcrack、Synchrony 或其他工具只能作为针对特定模式的候选；记录版本、参数和输出，不连续盲跑后覆盖原始输入。
- 借助 AST Explorer 检查最小节点结构；含敏感源码时用本地环境。

## 变换条件

- 标识符改名按 binding/scope 操作；区分对象键、标签、局部绑定、全局引用与导出 API。
- 常量折叠要考虑 NaN、Infinity、负零、BigInt、类型转换与异常。读取 getter/Proxy、调用函数不能默认纯净；静态分析结果不等于执行授权。
- 删除未引用声明前检查初始化副作用；例如 `const unused = sideEffect()` 的绑定未使用仍不能直接删除调用。
- `obj.method()` 改为独立函数调用会改变 this；合并或拆开逗号表达式时保留求值顺序和返回值。
- 恢复 switch/控制流时证明进入条件、状态更新、循环退出和异常路径；不确定的跳转保留并标注。
- 动态 eval/Function、异步 chunk 和模块初始化顺序需要单独证据。遇到 VM 字节码时先交付边界与假设，不能把美化输出称为反虚拟化完成。

## 验证与产物

每个有语义影响的阶段重新解析结果，记录变换数量和前后片段，并对可信样例比较输出、异常、可观察副作用和顺序。至少提供一个该规则不应改写的反例。执行未知目标需放在已选定的隔离运行环境；`node:vm` 本身不是安全隔离边界。

交付原始散列、工具与解析选项、阶段文件、变换前提、对照结果和未还原区段。恢复模块时另给依赖图或入口表；验证必须覆盖初始化副作用和至少一个懒加载路径（如果任务涉及）。API 参考：[Babel Traverse](https://babeljs.io/docs/babel-traverse)。
